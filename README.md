# ThreadSafeCache

## Особенность
Для реализации шаблонного класса `ThreadSafeCache` выбраны контейнеры STL `unordered_map` и `list` ради временной сложности O(1) для функций `get`, `set` и `remove`. `unordered_map` предоставляет O(1) при получении значений по ключу и добавлении новых пар ключ-значение. Однако для `unordered_map` не удастся реализовать эффективное распределение элементов по LRU, перемещение в этом случае будет в худшем случае делаться за O(n), а `list` предоставляет O(1) для этого. Поэтому для TTL-кэша с LRU-эвикцией используется `unordered_map`, где на каждый ключ приходится итератор от двусвязного списка пар ключ-значение в порядке от старых к новым, хотя можно и в порядке от новых к старым, временная сложность от этого не меняется. Для потокобезопасности используется мьютекс в обертке `lock_guard`, потому что каждая функция этого класса предполагает то или иное изменение кэша, в связи с чем каждый поток должен быть защищен от неподходящего изменения кэша от других потоков.

## Узкие места
У данной реализации ленивое удаление, то есть элементы с истекшим TTL удаляются только в случае получения их через `get`, из-за чего они останутся в кэше случае долгого не обращения к ним до завершения программы. Для решение этой проблемы можно реализовать создание фонового потока и удаление им элементов, у которых время закончилось.
